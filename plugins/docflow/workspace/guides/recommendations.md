# Source-aware recommendations

Start with the assignment, actual repository stack, native instructions, host,
actor and data policy. Use the bootstrap source and recommendation forms;
never invent schema fields. Catalogue revisions pin assets; record the exact
installed package revision or content hash with the observation/receipt too.
Replace example relative locations with verified accessible source locations
when adopting, including detached installs. A source URL is not installed
availability or authority.

| Action | Meaning | Before acting |
|---|---|---|
| reference | Read applicable guidance | Check source revision, scope and read access. |
| enable | Propose concrete installation/configuration | Name effects, dependencies, data destination, owner and success check; obtain missing setup authority before any change. |
| use | Apply an available procedure/tool | Recheck fit, actual availability, current compatible grant and native rules. |

Availability is `not_checked`, `not_present`, `present`, `enabled` or
`unavailable`. Present is not configured; enabled is not proof of a working
tool. Keep time/host/version observations in the recommendation's reason or
linked sourced knowledge, with machine-specific details in ignored local
state. Never put credentials in shared records.

## Examples to adapt

| Assignment | Recommendation | Availability and fallback |
|---|---|---|
| Documentation review | Add nothing; use existing ordinary file reads under the read scope. Empty recommendations are valid. | Verify current host tools; missing search falls back to opening named files. |
| React review | Reference the member's pinned React guidance and the reviewer profile only if applicable. | Start not_checked; missing guidance stays an explicit gap. Native instructions and file inspection remain usable. |
| Svelte/Tauri work | Reference native Rust/Svelte instructions; choose a domain specialist only when actual coverage exists. | React-only guidance is incompatible; report unavailable specialist instead of substituting it. |
| Proven retrieval gap | Suggest enabling the experimental local retrieval recipe for selected records only. | Deferred until dependencies, local data scope and setup authority are known; file search remains available. |

Use `workspace-recommendation.json` for structured entries, setting the
actual source/asset/revision, fit, reason, scope, availability, state,
authority or null, setup dependency or null, fallback and success check.
A selected recommendation with null authority is still only a choice.
Source selection candidate/approved/retired is independent of compatibility
proposed/tested/limited. None of these labels grants permission.

Retain unchanged declined/deferred choices. When host, actor, stack, source
revision, scope or data policy changes, append a reasoned re-evaluation:
retain the old entry, mark it superseded where appropriate, and add the
replacement. Do not overwrite historical selected/used evidence. Resolve
native aliases uniquely; conflicting member setup blocks dependent changes.

The brief records selected_assets; the receipt records used_assets with
actual results. A recommendation that was never loaded is not successful use.
Reconcile source evidence before updating shared knowledge. No source
catalogue entry runs an installer or launches an actor.
