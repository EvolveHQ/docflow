# docflow — PR #5 and project audit

**Verdict: request changes.** Five PR findings and three wider project gaps. P1 = resolve before relying on the affected workflow; P2 = correctness or consistency work to prioritise next.

**Scope:** internal review, 11 September 2026. [PR #5](https://github.com/EvolveHQ/docflow/pull/5), head `a6a1d45`, against `main` at `78f2021`; all 16 changed files, the wider skill set, conventions, test harness and queue. Latest GitHub release: [v0.9.4](https://github.com/EvolveHQ/docflow/releases/tag/v0.9.4). The local candidate checkout is older; review used a separate copy of the PR head.

**Functionality and usefulness:** the core proposition is useful for teams keeping decisions and implementation history in Git. Shared skill sources, optional layers, express bootstrap and retrofit support make adoption practical. Deriving coordination from Git removes a source of stale records. These are design strengths; improved delivery speed or reduced maintenance cost was not demonstrated by the evidence reviewed. Autonomous coordination is the weakest area. See the [product overview](https://github.com/EvolveHQ/docflow/blob/a6a1d458cf45c072802b705b5906f7faa3cf6cec/README.md#L121).

**PR findings**

| Priority | Finding and reason | Required correction |
|---|---|---|
| P1 · R1 | **PR integration assumes a branch that two modes never create.** Bootstrap drops the claim step for a single writer; shared checkout claims on the item. The [integration step](https://github.com/EvolveHQ/docflow/blob/a6a1d458cf45c072802b705b5906f7faa3cf6cec/plugins/docflow/skills/bootstrap/templates/_agent-prompts-autonomous.md#L103) nevertheless assumes a pushed claim branch, and [shipping](https://github.com/EvolveHQ/docflow/blob/a6a1d458cf45c072802b705b5906f7faa3cf6cec/plugins/docflow/skills/ship-item/SKILL.md#L115) also deletes it for shared checkout. These supported combinations cannot follow the instructions as written. | Separate the integration branch from the claim mechanism. Create/push a normal PR branch where needed; delete claim refs only in the mode that creates them. |
| P1 · R2 | **A successful push does not prove exclusive ownership.** The [claim step](https://github.com/EvolveHQ/docflow/blob/a6a1d458cf45c072802b705b5906f7faa3cf6cec/plugins/docflow/skills/bootstrap/templates/_agent-prompts-autonomous.md#L34) treats push rejection as exclusion. Local Git dry-runs accepted both an existing claim's descendant and its identical tip, each with exit 0. Another writer can therefore succeed without acquiring a new claim. [Git documents these push semantics](https://git-scm.com/docs/git-push). | Specify atomic creation only when the ref is absent, plus explicit ownership/resume handling. Test simultaneous claims, existing refs and retries. |
| P2 · R3 | **Audit can reject a valid PR awaiting merge.** [Check 10](https://github.com/EvolveHQ/docflow/blob/a6a1d458cf45c072802b705b5906f7faa3cf6cec/plugins/docflow/skills/audit/SKILL.md#L169) fails when a claim has no `plan/todo` file, while [shipping](https://github.com/EvolveHQ/docflow/blob/a6a1d458cf45c072802b705b5906f7faa3cf6cec/plugins/docflow/skills/ship-item/SKILL.md#L44) deliberately moves that file before the PR is ready. Re-auditing that branch can report a false orphan. | Resolve the item against the integration branch, PR state and corresponding done entry; distinguish pending integration, shipped leftovers and genuinely missing items. |
| P2 · R4 | **A valid shared-checkout claim is classified as stale.** The [stale rule](https://github.com/EvolveHQ/docflow/blob/a6a1d458cf45c072802b705b5906f7faa3cf6cec/plugins/docflow/skills/audit/SKILL.md#L172) uses absence of a remote claim branch for item claims, although shared checkout intentionally has no such branch. | Apply branch-based staleness only to branch claims; require completion or abandonment evidence for shared-checkout claims. |
| P2 · R5 | **Draft PR timing contradicts the ownership contract.** [agent-wave](https://github.com/EvolveHQ/docflow/blob/a6a1d458cf45c072802b705b5906f7faa3cf6cec/plugins/docflow/skills/agent-wave/SKILL.md#L127) opens it while claiming; the [run prompt](https://github.com/EvolveHQ/docflow/blob/a6a1d458cf45c072802b705b5906f7faa3cf6cec/plugins/docflow/skills/bootstrap/templates/_agent-prompts-autonomous.md#L43) waits until integration. Under the latter path, reserved identifiers and owned artefacts are unavailable in the PR during implementation. | Choose one timing and align the prompt, skill and templates. Publish ownership before concurrent implementation starts. |

R1 and R5 independently confirm the existing automated review comments; they remain present at the reviewed head.
