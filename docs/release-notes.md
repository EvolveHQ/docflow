# Release notes

## 0.10.0 — portable workspaces

This minor release adds portable workspace memory around independent member
repositories. It supplies fourteen skills: the nine repository lifecycle
skills and five workspace commands — setup, status, scope, dispatch and sync.
Workspace records cover ideas, decisions, work, knowledge and runs, with
committed operator mandate notes for source-bound authority. Members keep
their own instructions, histories, queues and completion events.

The complete package includes the schema, deterministic validator, asset
resolver, bootstrap templates, synthetic workspace and repository examples,
four starter roles and profile forms, and seven native host guides. External
sources can be recorded by content digest; remote-only repositories remain
references; imported history is kept distinct from grant-bound execution.
The glossary has one canonical two-column table, with a reviewed migration
path for existing documents.

One skill source is packaged for Claude Code, pi, Codex, OpenCode, Grok,
Cursor, omp and Copilot. Installation packaging and source-checked guides
are distinct from native behavioural acceptance. Full qualification of the
combined package across all eight hosts, the complete workspace scenario
family and real operator adoption remains pending. The deterministic suite
provides hostless evidence only. Earlier native observations apply to their
recorded snapshots, rather than certifying this release's bytes.

Clarity integration and desktop installer publication are parked and are not
part of this release. Docflow's ordinary-file workflows and validator can be
used independently. A ready candidate or green local check does not mean the
release is published: the checked PR must be merged, the exact version tagged
and the npm package published under the release controller's authority.

For adoption, use the [workflow guides](https://evolvehq.github.io/docflow/workflows/)
and [portable workspace overview](https://evolvehq.github.io/docflow/workspace/).

### Upgrade

Keep all fourteen skills and the complete sibling workspace assets from the
same version. Inspect changes in scratch first. Upgrading the plugin does not
replace adopter records, templates or member repositories, and it does not
require native identifier renumbering. For detached copies, keep the complete
workspace directory at `docflow-workspace/` beside `skills/`; symlinks resolve
the original plugin's sibling assets. Revalidate existing records with an
actual UTC evaluation time before any authority-dependent action.
