# ADR 0053 — Portable workspace operating skills

## Context

The reviewed W1/W2 contract is integrated at 9f748b806e9ab8eb8985e05d437f5c5f356dd248. Parent document 14 revision 0.15 authorises W3 as prompt-led operating skills, with Docflow owning canonical records and native hosts executing assignments. This records the existing development mandate, not a new human signature.

## Capability statement

Four disjoint workspace skills guide deliberate setup, read-only orientation, planning and authorised coordination using the reviewed schema exactly. They preserve the nine repository workflows, native ownership, selection/agreement/authority separation and source-bound receipt reconciliation. All templates remain flat in bootstrap; executable validators stay outside skills. Four portable roles, profile examples, source-aware recommendations, ordinary file search and six versioned native guides accompany the skills. Optional retrieval is an experimental recipe, never a mandatory service.

## User stories / scenarios

- A new participant learns owners, priorities, blockers and next actions from canonical files.
- An executor outside the workspace returns evidence for an authorised coordinator to reconcile.
- An adopter chooses a native host without installing a scheduler.

## Acceptance criteria

1. Each of the four skills declares inputs, effects, current authority, native claims, dependencies, resources, stopping point, receipt and unknown outcomes.
2. Assignment rechecks actor, scope, revision, expiry and revocation; denial stops the action across routes, contact loss preserves unresolved ownership, and completion preserves accepted agreement.
3. Four schema-valid starter roles and profile examples provide source-pinned reference/enable/use guidance, availability, stale/declined handling and an add-nothing option.
4. Six guides name Orca, Cursor, Claude Code, DeepSeek Harness, ZCode and Codex App with installed-tool or official primary-source command evidence and separate unrun smoke status.
5. All thirteen skills and complete assets resolve in plugin, npm and detached-copy layouts without source-checkout assumptions or hidden executables; upgrade/removal preserves adopter files.
6. Static, workspace and installer controls pass on a signed source; the task PR has current-head required CI and a source-bound review receipt.

## Out of scope

Native full host/scenario qualification (D4/W4/W5), Clarity edits, main integration, release, version bump, service/scheduler and automatic launch.

## Open questions

None blocking the bounded implementation; qualification remains separately queued.
